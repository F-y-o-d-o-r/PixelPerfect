## 2. Спецификация UI/UX

### 2.1. Автоматическая адаптация под тему macOS (Dark / Light Mode)

Интерфейс плавающего окна и всех вспомогательных окон расширения изначально проектируется под глубокую интеграцию с эстетикой macOS.

#### Логика работы:
1. **Режим по умолчанию — «System»:**
   - Расширение отслеживает системную тему macOS в реальном времени через медиа-запрос:
     ```typescript
     const mediaQuery = window.matchMedia('(prefers-color-scheme: dark)');
     mediaQuery.addEventListener('change', (e) => {
       if (currentSetting === 'system') {
         applyTheme(e.matches ? 'dark' : 'light');
       }
     });
     ```
   - При смене темы в macOS (вручную в Центре управления или автоматически по расписанию «День/Ночь») интерфейс плагина переключается мгновенно без перезагрузки и мерцания.
2. **Ручной выбор в настройках:**
   - Пользователь может принудительно зафиксировать тему:
     - `System` (авто-детект macOS, по умолчанию)
     - `Dark` (тёмная тема — 100% бесплатна из коробки)
     - `Light` (светлая тема)
   - Выбранная опция сохраняется в `chrome.storage.local`.
3. **Цветовая палитра (Apple Design Guidelines):**
   - **Dark Mode:**
     - Фоновый цвет окна: `#1C1C1E` (Apple System Background Dark).
     - Поверхности карточек/панелей: `#2C2C2E` (Secondary Background).
     - Разделители и границы: `rgba(255, 255, 255, 0.12)`.
     - Текст: `#FFFFFF` (Primary), `#8E8E93` (Secondary).
     - Акцент: `#007AFF` (Apple System Blue) / фирменный кобальтовый синий `#2B6CB0`.
   - **Light Mode:**
     - Фоновый цвет окна: `#F5F5F7` (Apple System Background Light).
     - Поверхности карточек: `#FFFFFF`.
     - Разделители и границы: `rgba(0, 0, 0, 0.08)`.
     - Текст: `#1C1C1E` (Primary), `#6E6E73` (Secondary).
     - Акцент: `#007AFF`.

### 2.2. Окно настроек: Многопоточная кинематика жидкого матового стекла (Multi-Ribbon Fluid Glass)

> **Статус концепта:** Набросок / вариант в изучении.  
> **Контекст применения (2 варианта реализации):**
> 1. *Вариант А (Side Panel Overlay):* Оверлей наплывает поверх интерфейса самой боковой панели расширения.
> 2. *Вариант Б (Full Viewport / Webpage Overlay):* Оверлей внедряется через Content Script поверх **всей веб-страницы целиком** (во весь экран браузера), размывая текущую верстку сложными потоками жидкого стекла и открывая центральный блок настроек.

Окно настроек открывается не плоскими шторками, а сложной многослойной волной полупрозрачных матовых потоков (лент/рукавов), наплывающих с обеих сторон с разной скоростью, задержками и органическими траекториями, словно северное сияние или потоки жидкого стекла (Aurora Glass).

#### Кинематика многопоточного наплыва:
1. **Каскад потоков (6 асинхронных стеклянных лент):**
   - **Поток L1 (верхний левый, стремительный луч):** задержка `0ms`, длительность `380ms`. Вылетает под легким углом `skewX(-6deg)`, неся за собой первую волну легкого размытия (`blur(12px)`).
   - **Поток R1 (верхне-средний правый, широкий накат):** задержка `60ms`, длительность `420ms`. Выплывает навстречу L1, мягко перекрывая верхнюю треть экрана.
   - **Поток L2 (центральный левый, плотный глубокий рукав):** задержка `110ms`, длительность `440ms`. Главный массив размытия (`blur(24px)`), накрывающий рабочую зону слоев.
   - **Поток R2 (нижне-средний правый, контр-поток со световым ребром):** задержка `160ms`, длительность `400ms`. Наплывает на нижнюю половину окна.
   - **Поток L3 (нижний левый, стелющийся шлейф):** задержка `210ms`, длительность `360ms`. Закрывает нижний левый угол.
   - **Поток R3 (финальный правый гребень):** задержка `250ms`, длительность `340ms`. Завершает перекрытие правого нижнего края.

2. **Органическая форма и световые грани (Caustic Rims & Specular Sheen):**
   - Передняя кромка каждого потока имеет органическое волнообразное скругление (`border-radius: 9999px`), а не прямую грань.
   - На гребне каждого рукава идет динамический стеклянный блик (неоновая грань `box-shadow: 0 0 20px rgba(255, 255, 255, 0.45)`), подчеркивающий границу текущей волны.
   - При пересечении потоков размытие и насыщенность органически перемножаются (`backdrop-filter: blur(28px) saturate(200%)`).

3. **Коалесценция и световой проход (Merge & Specular Sweep — t = 360ms -> 460ms):**
   - В точке полного схождения потоки бесшовно сливаются в единую монолитную плоскость матового стекла.
   - По диагонали стекла прокатывается быстрый световой блик (Specular Gleam Sweep), создавая тактильное ощущение только что застывшего премиального стекла.

4. **Кристаллизация контента (Staggered De-blur Entrance — t = 280ms -> 500ms):**
   - Содержимое настроек не просто меняет `opacity`, а «выныривает» из глубины размытия:
     - `filter: blur(10px) -> blur(0px)`
     - `transform: translateY(14px) scale(0.97) -> translateY(0px) scale(1)`
     - Каскад элементов: Заголовок -> Блок тем macOS -> Настройки хоткеев -> Управление брейкпоинтами.

5. **Кинематика закрытия (Fluid Dissolve & Recede — 280ms):**
   - Контент мгновенно уходит в глубину (`opacity: 0, scale: 0.98, filter: blur(6px)`).
   - Потоки ускоренно сглаживаются и разъезжаются обратно к краям экрана с легким градиентным растворением (`ease-in`).

> [!NOTE]
> Весь раздел 2.2 (стеклянное окно настроек) **отложен после MVP**: шесть лент с `backdrop-filter` на весь viewport тяжёлые для GPU на сложных страницах и противоречат принципу «лёгкий и быстрый». В MVP настройки — простое выпадающее меню. Ниже — референсный CSS; при реализации писать на Sass (`.sass`, indented).

### 2.3. Форм-фактор интерфейса: Плавающее окно и превосходство над PerfectPixel

В качестве базового UX-референса берется проверенная временем эргономика плавающего окна поверх страницы, но с полным устранением недостатков и багов PerfectPixel.

#### 1. Два состояния интерфейса (State Model):

* **Свернутое состояние (Mini-Bar / Компактная плашка):**
  * Тонкая элегантная пилюля, прикрепленная к краю экрана или свободно плавающая.
  * **Содержимое (минимализм без лишнего шума):**
    * `[ + ]` / `[ − ]` — переключатель разворачивания/сворачивания основной панели.
    * `👁 Show / Hide` — быстрый показ/скрытие активного слоя (хоткеи: `Space` или `H`).
    * `🔒 Lock` — быстрый тумблер режима `pointer-events: none` (позволяет кликать и инспектировать верстку в DevTools прямо сквозь макет).
    * *(Убрано по требованию)*: выпадающий список режимов наложения (`Normal ▾`) полностью исключен из свернутого вида, чтобы не перегружать интерфейс.

* **Развернутое состояние (Expanded Panel):**
  * Полноценная карточка управления слоями:
    * **Шапка:** Логотип `Pixel Perfect by ITITI`, тумблер `🌙 Dark Mode` (100% бесплатно), кнопка меню `☰` (с настройками и хоткеями), кнопка сворачивания `[ − ]`.
    * **Добавление слоев (`MockupImportBar`):**
      * Вынесено в отдельный монолитный бар высотой 34px над папками с нейтральным оформлением:
        1. `📋 Paste (Cmd + V / Ctrl + V)` — приоритетный сценарий: скопировал фрейм в Figma $\rightarrow$ нажал `Cmd + V` $\rightarrow$ макет уже на странице.
        2. `⬆ Upload` — стандартный выбор локального файла с диска (PNG, JPG, SVG, WebP).
        3. `Drag & Drop` — перетаскивание картинки прямо в область виджета или на экран.
    * **Быстрый бар активного макета (`.pp-quickbar`):**
      * 2-секционный монолитный бар `[ 👁 Скрыть s ] | [ 🔒 Двигать i ]`. Обе кнопки имеют нейтральный цвет (без перекрашивания в синий при включении режима движения).
    * **Управление списком слоев:** карточки слоев с превью, переключение вида (Сетка / Список), возможность создания папок (лимит бесплатных слоёв задаётся конфигом, см. раздел 5).
      * *Архитектура папок (вдохновлено лучшим из Pro-версии, но бесплатно):*
        * Корневой уровень: папки отображаются как вкладки с компактным счетчиком макетов (14px таблетки со шрифтом 8px, например `📁 Components (6)`, `📁 Pages (4)`), рядом с отдельными слоями.
        * Внутри папки: изолированная сетка макетов + кнопка `+ Добавить папку`.
    * **Блок позиционирования (Origin Controls):**
      * Цифровые поля координат `X` и `Y` (шаг 1px / 10px) с компактной шириной и кнопками быстрого прижатия:
        * **Ряд 1:** кнопка центрирования активного макета по горизонтали (`snapActiveLayerCenterX`) с подсказкой `x` в правом нижнем углу + поле X.
        * **Ряд 2:** кнопка прижатия активного макета к верхнему краю (`snapActiveLayerTopY`, `Y: 0`) с подсказкой `y` в правом нижнем углу + поле Y.
        * **Ряд 3:** кнопка инверсии цветов `[ ◐ ]` слева от группы `[ 1x | 2x | Auto ]`. По клику в 1 нажатие мгновенно включает/выключает режим инверсии (`filter: invert(1)` с подсказкой хоткея `v`), идеально подходящий для сверки светлых макетов на тёмных темах сайтов, без громоздких выпадающих меню. Продвинутое попиксельное сравнение `Smart Diff` запланировано на отдельном Offscreen Canvas без искажений Shadow DOM.
      * D-Pad стрелок для быстрого клика мышью:
        * В центре D-Pad (между стрелками): смарт-кнопка **`⌖ Прижать к началу` (Snap to Top-Center)** с идеально центрированной векторной SVG-иконкой. В 1 клик центрирует по горизонтали `X` и прижимает к верху `Y = 0`.
      * **Тумблер Retina `[ 1x | 2x | Auto ]`** — устранение бага PerfectPixel, где на Retina-дисплеях картинка сжимается в 2 раза до `0.5x`. При наведении на активную кнопку сохраняется белый цвет текста с плавной сменой оттенка фона.
      * Ползунок прозрачности (`Opacity: 0–100%`) с математически идеальным субпиксельным вертикальным центрированием бегунка (`margin-top: -5px` для 14px кружка на 4px треке), раздельными правилами WebKit и Firefox и без блокировки хоткеев клавиатуры.
    * *(Нижняя панель инструментов — сетки, измерительный крест из Pixel Parallel и Smart Diff — запланированы на Шаг 2, первая версия выходит максимально компактной и быстрой).*

#### 2. Верхнее меню настроек (`☰ Hamburger Menu`):
* Выпадающее меню в правом верхнем углу (по образцу, но с нашими фичами):
  * `⚙️ Настройки` — вызов окна настроек с анимацией матового стекла (Dual-Stream Glass).
  * `🪟 Открыть в боковой панели (Side Panel)` — **после MVP** (требует второй интерфейс и синхронизацию состояния; Vim-режим в панели не работает).
  * `⌨️ Горячие клавиши (Hotkeys)` — подсказка по управлению стрелками (1px / 10px), Space, H.
  * `💬 Сообщить о баге / Обратная связь` — быстрая ссылка на GitHub Issues / Support.
  * Версия расширения (`v1.0 MVP`).

#### 3. Свободное перетаскивание и прилипание (Draggable & Magnetic Docking):
* Виджет можно схватить за шапку и перетянуть в **любую часть окна** (левый верх, правый верх, центр, низ экрана), чтобы он не загораживал тестируемую часть верстки.
* Умное магнитное прилипание к углам и краям страницы.
* Координаты положения плашки сохраняются в `chrome.storage.local` для каждого домена.

### 2.4. Система горячих клавиш: Нативная поддержка Vim-стиля (Vim Ergonomics)

Для разработчиков, привыкших к Vim / Neovim / Vim-mode в VS Code и JetBrains, предусмотрено полное модальное управление макетом с домашнего ряда клавиатуры (home row) без необходимости тянуться к мышке или блоку стрелок.

#### Двухрежимная модель (Locked vs Nudge):

1. **Режим «Закреплен» (Locked / Click-Through Mode — базовое состояние):**
   * Макет зафиксирован на координатах (`pointer-events: none`).
   * Все клики мыши, скролл и выделение текста идут напрямую в вёрстку страницы (можно свободно кликать ссылки, кнопки и инспектировать элементы в DevTools).
   * Клавиши `h/j/k/l` не сдвигают макет, чтобы не мешать навигации по странице.

2. **Вход в режим позиционирования (Nudge Mode):**
   * Нажатие клавиши **`i`** (Insert/Edit в Vim) или тумблера **`x`**:
     * С макета снимается блокировка.
     * По периметру макета появляется тонкая светящаяся рамка и индикатор статуса `[NUDGE: h, j, k, l]`.
     * Клавиши **`h`, `j`, `k`, `l`** передвигают макет на **1px** (`Shift + h/j/k/l` — на **10px**).

3. **Моментальное закрепление обратно (Lock & Exit):**
   * Нажатие классической для Vim клавиши **`Esc`** (или повторное нажатие **`x`** / **`Enter`**):
     * Макет мгновенно **закрепляется на новых координатах** (`pointer-events: none`).
     * Светящаяся рамка исчезает, кликабельность возвращается сайту.
   * **Результат:** разработчик нажимает `i` $\rightarrow$ подгоняет макет пальцами на `h/j/k/l` $\rightarrow$ нажимает `Esc` (закрепил). Всё за секунду без отрыва рук от клавиатуры!

#### Таблица горячих клавиш:

| Действие | Vim-клавиши | Стандартные клавиши | Описание |
| :--- | :--- | :--- | :--- |
| **Разблокировать для сдвига** | **`i`** | Клик по замку `🔒` | Переход в Nudge-режим сдвига макета |
| **Закрепить обратно (Lock)** | **`Esc`** | Клик по замку `🔒` | Фиксация макета и возврат кликов верстке сайта |
| **Микро-сдвиг (1px)** | `h` (влево), `j` (вниз), `k` (вверх), `l` (вправо) | `←`, `↓`, `↑`, `→` | Подгонка (только в Nudge-режиме) |
| **Быстрый сдвиг (10px)** | `Shift + h / j / k / l` | `Shift + стрелки` | Шаг 10px (только в Nudge-режиме) |
| **Прижать к началу** | `0` | `Home` | Центр по X и `Y=0` (глобально в Nudge и Locked режимах) |
| **Центрировать по X** | `x` | Кнопка `[ ⇋ ]` | Центр по горизонтали (X: Center) |
| **Прижать к верху Y** | `y` | Кнопка `[ ⇈ ]` | Верхний край (Y: 0) |
| **Сброс параметров** | `r` | `R` / кнопка «Сброс» | Сброс макета к (0,0), 1x, Normal, 50% |
| **Показ / Скрытие макета** | `s` | Кнопка «Скрыть / Показать» `👁` | Показать или скрыть активный макет (глобально) |
| **Инверсия цветов** | `v` | Кнопка `[ ◐ ]` | Включение / выключение инверсии цветов (Normal / Invert) |

*Отложено на после MVP:* смена слоя (`w` / `b`), `g g`. Клавиши `Enter` и `H` убраны: у них была неоднозначность (`h` = влево).

* **Правила реализации Vim-режима:**
  * В режиме Locked слушается **только** вход (`i`) — остальные клавиши не перехватываются, чтобы не ломать хоткеи сайтов (Gmail, GitHub, Notion).
  * Клавиши определяются по `event.code` (`KeyH`, `KeyJ`…), а не по `event.key`, иначе на русской раскладке Vim-клавиши не работают.
  * Слушатель на `window` с `capture: true`. Проверка фокуса в поле ввода — через `event.composedPath()` и `isContentEditable` (события из Shadow DOM ретаргетятся).
  * `Esc` перехватывается (`stopImmediatePropagation`) только в Nudge-режиме.
  * Клик по странице в Nudge-режиме возвращает режим Locked.
  * Хоткеи активны только в режиме оверлея и автоматически отключаются при активном фокусе в полях ввода `<input>` / `<textarea>`.
  * Для всех клавиш навигации вызывается `e.preventDefault()`, что полностью исключает паразитный скролл веб-страницы при нажатии `j` / `k` (главная болезнь PerfectPixel).

### 2.5. Умная привязка к URL-страницам и адаптивные брейкпоинты

#### 1. Умная привязка папок и макетов к конкретным страницам (Smart URL-Path Binding):
* **Проблема конкурентов:** PerfectPixel сохраняет слои только на весь домен целиком (`localhost:3000` или `site.com`). Перешел с главной на `/catalog` или `/checkout` — на экране продолжает висеть чужой макет главной страницы, приходится вручную его скрывать и искать нужный.
* **Наше решение (Двухуровневая привязка Domain $\rightarrow$ URL Path):**
  * Состояние сохраняется с точностью до пути страницы: `Origin + Pathname` (например, `localhost:3000/` и `localhost:3000/cart`).
  * **Модель `UrlBinding`:** `type: 'exact' | 'prefix' | 'pattern' | 'domain'`. По умолчанию — точный путь; шаблоны вроде `/product/*` покрывают динамические маршруты (`/product/123`, `/product/456` — один макет). Порт и `www.` — нормализуются. Кнопка выбора: «этот путь / шаблон / весь домен».
  * **Детекция SPA-навигации:** `pushState` из изолированного мира content script перехватить нельзя. Использовать `chrome.webNavigation.onHistoryStateUpdated` (permission `webNavigation`, запрашивается опционально) из service worker + `popstate` в content script.
  * **Авто-ассоциация:** если пользователь загружает макет или создает папку, находясь на странице `/cart`, расширение автоматически присваивает им привязку `URL: /cart`.
  * **Авто-переключение на лету (SPA & Multi-page):**
    * Расширение слушает переходы браузера (события `popstate` / `pushState` в React, Next.js, Vue, Nuxt, а также события `chrome.tabs.onUpdated`).
    * Пользователь кликнул на сайте ссылку «О нас» (`/about`) $\rightarrow$ Pixel Perfect **сам моментально активирует папку «About» и макет страницы «О нас»**!
    * Вернулся в каталог (`/catalog`) $\rightarrow$ автоматически включился макет каталога.
  * **Кнопка-булавка на карточке:** `📌 Привязать к этой странице` / `🌐 Показать на всех страницах домена`.

#### 2. Адаптивные брейкпоинты (Responsive Breakpoints — Шаг 2):
* **Как реализовать без усложнения интерфейса (Zero-Config UX):**
  * Никакого нудного ручного ввода `min-width / max-width` в отдельных модальных окнах (это убивает скорость работы).
  * **Магия автоопределения по ширине картинки (Auto-Detect):**
    * Загрузил макет шириной 375–430px $\rightarrow$ расширение само понимает: это `📱 Mobile`.
    * Загрузил макет шириной 768–1024px $\rightarrow$ расширение маркирует его как `📟 Tablet`.
    * Загрузил макет шириной > 1024px $\rightarrow$ расширение маркирует его как `🖥 Desktop`.
  * **Быстрый тумблер в 1 клик на карточке слоя:** бейдж `[ 🌐 Все | 🖥 Desktop | 📱 Mobile ]`.
  * **Поведение при ресайзе (Responsive Auto-Switch):**
    * При изменении ширины окна браузера или эмулятора DevTools расширение само переключает активный слой: сузил окно до 390px $\rightarrow$ макет десктопа скрылся, макет мобилки включился.
  * **Этапность:** Авто-определение типа макета (по ширине) закладывается в базовую структуру данных сразу, а саму автоматическую смену при ресайзе активируем в Спринте 3 (Шаг 2).

### 3.1. Локализация (8 языков из `../ititi`) и Наблюдаемость (Логгер, Sentry, Amplitude)

1. **Автоматическая локализация под язык браузера (`src/i18n/`):**
   - Поддерживаются все **8 языков** основной экосистемы ITITI (`../ititi/src/i18n/config.ts` и `../EatRay`):
     - `en` (English — язык по умолчанию / fallback)
     - `ru` (Русский)
     - `uk` (Українська)
     - `el` (Ελληνικά)
     - `sr` (Српски)
     - `bg` (Български)
     - `ro` (Română)
     - `ka` (ქართული)
   - При первом запуске расширение считывает язык интерфейса браузера через `chrome.i18n.getUILanguage()` (или `navigator.language`), приводит его к двухбуквенному коду (`ru-RU` $\rightarrow$ `ru`) и проверяет наличие в списке поддерживаемых. Если язык поддерживается — активируется он; если нет — ставится `en`. В меню плавающего окна пользователь может переключить язык вручную.

2. **Логирование, Sentry и продуктовая аналитика Amplitude:**
   - **Логгер (`src/shared/logger.ts`):** единая обёртка с префиксом `[Pixel Perfect]`. В режиме разработки (`development`) выводит `debug` и `info`, в продакшене (`production`) — только `warn` и `error`, чтобы не спамить в DevTools разработчикам, которые верстают свои сайты.
   - **Отслеживание ошибок (`Sentry`):** используется изолированный `BrowserClient` (`@sentry/browser`) без глобальных обработчиков `window.onerror` чужой страницы, чтобы фиксировать только внутренние сбои самого расширения.
   - **Продуктовая аналитика (`Amplitude`):** отправляется из фонового Service Worker (`background/index.ts`) по HTTP API (так как внешние скрипты запрещены в Manifest V3, а Content Script ограничен CSP проверяемого сайта). Передаются исключительно обезличенные события фичей (`mockup_added`, `vim_nudge_toggled`, `free_limit_reached`) — без отправки URL страниц или изображений пользователя.

## 5. Монетизация, лимиты и юридические ограничения (зафиксировано 27.10.2026)

### 5.1. Принципы
- **Бесплатное ядро остаётся полноценным:** наложение макета, Vim-режим, Retina-тумблер, привязка к страницам, тёмная тема, папки. Это то, что привлекает и удерживает пользователей.
- **Лимит бесплатных слоёв сохраняем, но он не основной рычаг продаж.** Значения хранятся в одном месте — `FREE_LIMITS` в `shared/constants.ts` (папки, слоёв в папке), чтобы менять их без переписывания кода.
  - Ориентир: **3 папки × 5 слоёв** (15 слоёв). Исходная идея 3×3 выглядела слабо рядом с «free forever, unlimited» у Pixel Perfect Pro. Финальные цифры — после первых отзывов.
  - Пользователь упирается в лимит не сразу (нужно создать папки и наполнить их), поэтому лимит не мешает первому впечатлению.
- **Платить будут за экономию времени**, а не за счётчик слоёв: импорт из Figma по ссылке, Smart Diff, баг-репорт в 1 клик, командные возможности.

### 5.2. Тарифы (черновик, обсуждается)
| Тариф | Что входит | Когда |
| :--- | :--- | :--- |
| **Free** | Всё базовое ядро, лимит `FREE_LIMITS`, без рекламы | MVP |

### 5.3. Что можно без юрлица, а что только с юрлицом
> [!IMPORTANT]
> Условия платёжных сервисов, выплат и налогов зависят от страны резидентства. **Перед запуском биллинга проверить актуальные условия** выбранного сервиса именно для вашей страны и способа вывода денег.

**Без юрлица (физлицо / Individual):**
- Разработка, публикация расширения в Chrome Web Store (бесплатное расширение), Free-тариф.
- Продажа подписок через **Merchant of Record** (Lemon Squeezy, Paddle): сервис выступает продавцом, берёт на себя НДС/налоги и выдаёт покупателю чек/инвойс. Это основной путь. Stripe напрямую без юрлица — не планируем.
- Интеграции с Figma API, Jira, Notion, GitHub (регистрация приложения-разработчика, не требует юрлица).
- Supabase (Auth, БД, Edge Functions), Cloudflare Pages — бесплатные тарифы.
- Team-тариф вручную: клиент оплачивает через MoR, вы вручную подключаете его команду.

**Скорее всего потребуется юрлицо (или уточнять отдельно):**
- Договоры и счета на оплату под бухгалтерию крупных компаний (enterprise), безналичные платежи по счёту.
- Собственный эквайринг (Stripe/другие напрямую), собственная выплата зарплат/подрядчикам.
- Регистрация товарного знака, официальное юр. лицо в профиле разработчика Chrome Web Store (статус «Trader» для EU — может потребовать указать адрес и контакты; проверить при публикации).
- Стабильный доход выше порога, когда налоговая отчётность физлица становится неудобной (ориентир из `ROADMAP.md`: €1500–2000/мес).

### 5.4. Принципы защиты Pro
- Проверка статуса Pro на клиенте — «честная лицензия»: обойти её можно правкой в DevTools, и мы не тратим силы на DRM.
- Фичи, требующие сервера (Figma-прокси, командные пресеты, общие настройки), защищены проверкой JWT из Supabase.
- Supabase и биллинг в Спринты 1–2 **не входят** (сначала нужно собрать пользователей и отзывы).
