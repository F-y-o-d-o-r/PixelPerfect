## Правила работы ассистента

- **Обязательная синхронизация документации при любых изменениях:**
  - Каждый раз, когда в проект вносятся изменения (новые фичи, изменение горячих клавиш, UX-поведение, настройки, архитектурные решения) — ассистент **обязан актуализировать** `AGENTS.md`, `README.md` и соответствующие документы в `md/` (`ROADMAP.md`, `PLAN.md`). Документация всегда должна быть на 100% синхронизирована с кодом.

- **Чтение файлов и поиск (всегда разрешено без лишних сообщений):**
  - Чтение любых файлов проекта, поиск по коду, просмотр истории и логов разрешены свободно.
  - **Никогда не писать в чат**, какие строки или файлы просматриваются/читаются.

- **Команды Git:**
  - **Разрешено свободно выполнять:** любые информационные команды (`git status`, `git diff`, `git log`, `git show`, `git branch`).
  - **Строго запрещено выполнять без прямого явного указания пользователя:** `git add`, `git commit`, `git push`.
  - **Строго запрещено удалять что-либо:** любые деструктивные команды удаления (`rm`, `git rm`, `git reset --hard`, `git clean`, удаление веток).

- **Предупреждения и объяснение плана перед действием:**
  - Прежде чем изменять файлы проекта, запускать команды сборки или скрипты — сначала всегда написать пользователю понятный план: что именно планируется сделать и зачем. Только после объяснения приступать к действию.

## Технологический стек (расширение для Chrome)

- **Платформа:** Google Chrome Extension Manifest V3 (Content Scripts; Side Panel API — только после MVP).
- **Фреймворк:** Vue 3 (Composition API) + TypeScript.
- **Пакетный менеджер:** Yarn (`yarn`, не использовать `npm`).
- **Сборщик:** Vite.
- **Линтер и форматирование:** ESLint (flat config `eslint.config.js` с `@eslint/js`, `typescript-eslint`, `eslint-plugin-vue`, `eslint-config-prettier`) + Prettier. Обязательный запуск `yarn lint` и `yarn typecheck` при любых изменениях.
- **Стили:** Sass (Indented syntax, `.sass`) — синтаксис чисто на отступах без фигурных скобок `{}` и точек с запятой `;`.
- **Изоляция UI:** Web Components / Shadow DOM (`mode: 'open'`) для плавающего окна (абсолютная изоляция стилей виджета и страницы):
  - Подъём хост-элемента в **Top Layer браузера** (`popover="manual"` + `showPopover()`), чтобы нативные `<dialog>` и модальные окна страницы никогда не перекрывали плавающее окно.
  - Защита `MutationObserver` от блокировки модалками (`Radix UI`, `Headless UI`, `MUI`), автоматически снимающая атрибуты `inert` и `aria-hidden="true"` с хост-элемента расширения.
  - Изоляция оверлея макета через `overflow-x: clip`, чтобы сдвинутый за правый край экрана макет не вызывал ложный горизонтальный скролл на сайте.
- **Бэкенд, Auth & БД:** Supabase (PostgreSQL, Google OAuth через `chrome.identity.launchWebAuthFlow` + PKCE, Edge Functions, бесплатный тир до 50k MAU).
- **Хранение данных:** Единая модель в `chrome.storage.local` с разрешением `"unlimitedStorage"` (без `IndexedDB` и без `window.localStorage` сайта):
  - Метаданные слоёв, папок и состояние плавающего окна хранятся в отдельных лёгких ключах (`pp_ititi_layers`, `pp_ititi_folders`, `pp_ititi_floating_window`) — обновляются мгновенно при сдвиге координат.
  - Строгая модель «Страницы/Папки»: макетов без папки не существует. При первом старте автоматически создаётся `Page 1`. Любой загружаемый макет всегда принадлежит текущей активной странице. Лимиты Free: до 3 страниц по 3 макета на каждой (всего до 9 макетов под Desktop, Tablet, Mobile). Переключение страниц осуществляется через горизонтальные вкладки-табы в 1 клик с нативным горизонтальным скроллом тачпадом. Чёткие контрастные бейджи количества макетов на табах. Имя вкладки и заголовок секции обрезаются троеточием (`text-overflow: ellipsis`) при длинных названиях с показом полного имени в тултипе `:title` при наведении. Умная генерация имён без дубликатов (`Page 1`, `Page 2`, `Page 3`...). Защита от удаления единственной оставшейся страницы (кнопка 🗑️ отключается с подсказкой `toastCannotDeleteLastFolder`). Перемещение макетов между страницами через Drag & Drop на таб с белым курсором-крестиком (`cursor: move`). При переключении страницы автоматически выбирается тот макет, который был активным на ней последним (`Folder.lastActiveLayerId`), иначе первый; на пустой странице активного макета нет.
  - Сами картинки макетов хранятся в `chrome.storage.local` каждая под своим изолированным ключом `pp_ititi_blob_<layerId>` в модуле `blobStorage.ts` (записываются 1 раз при добавлении и не перезаписываются при перемещении макета). Конвертация Data URL в бинарный Blob происходит синхронно через `atob` + `Uint8Array`, исключая сетевые вызовы `fetch` и гарантируя полную совместимость с Content Security Policy (CSP) любых сайтов. Поддерживаются растровые (`PNG`, `JPEG`, `WebP`) и векторные (`SVG`) макеты, а также прямая вставка SVG из Figma через буфер обмена. Для SVG автоматически определяются проектные размеры через `viewBox` и атрибуты ширины/высоты, а MIME-тип нормализуется в `image/svg+xml`.
  - Изменение порядка макетов (Reordering): внутри страницы макеты можно свободно менять местами простым перетаскиванием (Drag & Drop) карточки или строки с наглядной неоновой линией вставки (Drop Indicator Line), позиционируемой ровно в межблочный зазор (в межколонный зазор 6px в сетке и межстрочный зазор 6px в списке с идеальным 2px центрированием и без искажающего масштаб сжатия карточки).
  - Секция макетов, сетка и отступы: ширина плавающего окна 312px (по эталону PerfectPixel), карточки макетов отображаются в сетке `repeat(3, minmax(0, 1fr))` с `gap: 6px` и авто-переносом на следующую строку без горизонтального скролла окна (`overflow-x: hidden`). Карточки и полоски списка имеют чистый фон `var(--bg-secondary)` (белый в светлой теме), а название активной страницы в шапке секции сохраняет естественный регистр (без принудительного `uppercase`). Отступы между верхними кнопками (`.pp-add-row`), вкладками страниц (`.pp-pages-bar`) и секцией макетов (`.pp-section-bar`) сбалансированы по 6px, а кнопки действий имеют компактный размер 24×24px.
  - Благодаря хранению в `chrome.storage.local` без фильтрации по `origin`, все папки и макеты доступны глобально на любых окружениях (`localhost`, `staging`, `production`) и не стираются при вызове `localStorage.clear()` на сайте.
  - Профили, статус Pro и лицензии — в Supabase.
- **Библиотека визуального сравнения:** GPU-оверлей в реальном времени + `pixelmatch` на `OffscreenCanvas` в фоновом Offscreen Document (Smart Diff).
- **Локализация (i18n):** Расширение локализуется на 8 языков экосистемы ITITI (`en`, `ru`, `uk`, `el`, `sr`, `bg`, `ro`, `ka`). При запуске автоматически определяется язык браузера (`chrome.i18n.getUILanguage()` / `navigator.language`). Если язык браузера входит в список поддерживаемых — выбирается он, иначе по умолчанию ставится английский (`en`). Пользователь также может переключить язык вручную.
- **Логирование и аналитика:**
  - Структурированный клиентский логгер (`src/shared/logger.ts`): в `development` выводит все уровни (`debug`, `info`, `warn`, `error`), в `production` — только ошибки и критические предупреждения, не засоряя консоль сайта.
  - Отслеживание ошибок: Sentry (изолированный `BrowserClient` только для ошибок внутри расширения, без перехвата ошибок хост-страницы).
  - Продуктовая аналитика: Amplitude (отправка анонимных продуктовых событий через фоновый Service Worker по HTTP API без передачи URL или пользовательских макетов).

## Архитектура UI, горячие клавиши и UX-поведение

- **Режим подсказок клавиш (`?` / `Shift + /`):**
  - По умолчанию интерфейс чистый, подсказки скрыты.
  - При нажатии `?` на клавиатуре или кнопки `?` в шапке окна включается/выключается режим показа подсказок (состояние сохраняется в `windowState.showHotkeys`).
  - Все подсказки выводятся единым серым цветом (`.pp-hotkey-hint`, `9px`, `var(--text-muted)`) без скобок рядом с элементами управления.

- **Таблица горячих клавиш:**
  - **`s`**: показать / скрыть активный макет (`Show / Hide`). Кнопка «Скрыть / Показать» (как в окне, так и в свёрнутом минибаре) всегда сохраняет нейтральный цвет, не перекрашиваясь в синий.
  - **`i`**: режим сдвига / закрепление макета (`Move / Lock`), также `Esc` для закрепления.
  - **`m`**: свернуть / развернуть плавающее окно (`Minimize / Expand`).
  - **`u`**: открыть системный диалог загрузки файла (`Upload`). Кнопка «Загрузить» продублирована в шапке секции «МАКЕТЫ».
  - **Подтверждение удаления:** перед удалением макета или страницы показывается локализованный `confirm` (`confirmDeleteMockup`, `confirmDeletePage`); для единственной страницы вопрос не задаётся (удаление запрещено).
  - **`⌘V` / `Ctrl+V`**: вставка макета напрямую из буфера обмена.
  - **`h / j / k / l` или стрелки**: сдвиг макета на 1px.
  - **`Shift + (h/j/k/l / стрелки)`**: сдвиг макета на 10px.
  - **`0` / `Home`**: отцентрировать макет по горизонтали и прижать к верхнему краю (`X: Center, Y: 0`).
  - **`1` – `9`**: быстрое переключение прозрачности (`10%` – `90%`).
  - **`-` / `+` (или `[` / `]`)**: изменение прозрачности с шагом `10%` (с `Shift` — шаг `1%`).
  - **Колесо мыши над макетом (в режиме сдвига)**: регулировка прозрачности с шагом `5%`.
  - **`⌥ / Alt` (при перетаскивании макета или окна)**: временное отключение магнитного прилипания к краям и центру.

- **Поведение плавающего окна и уведомлений (Toasts):**
  - **Центрированные системные тосты:** Всплывающие уведомления (режим сдвига, закрепление, сброс координат, лимиты, переключение макетов, ошибки) отображаются строго **внизу по центру экрана** (`bottom: 24px`, `left: 50%`, `transform: translateX(-50%)`) в виде эстетичной парящей капсулы с эффектом блюра (`backdrop-filter: blur(8px)`).
  - **Симметрия мыши и клавиатуры:** Любое действие (переключение режима сдвига/закрепления, выбор макета, скрытие/показ) вызывает одинаковый мгновенный отклик в тосте как при нажатии клавиш (`i`, `s`), так и при клике мышью.
  - **Магнитное прилипание:** окно магнитится ко всем 4 углам экрана, 4 сторонам и к центру экрана (по X и Y) с порогом 20px.
  - **Адаптивные углы:** углы окна становятся прямыми (`border-radius: 0`) только на тех сторонах, которые прижаты к краю экрана; свободные углы остаются скругленными.
  - **Авто-подтягивание при разворачивании:** если окно в свёрнутом виде находилось внизу экрана, при разворачивании через `+` или `m` оно автоматически подтягивается вверх и прилипает к нижней границе, не выходя за пределы экрана.
  - **Трёхпозиционная тема:** кнопка в шапке окна циклически переключает `🌙 Тёмная` → `☀️ Светлая` → `🌗 Авто (Системная)`.
  - **Локализация:** поддержка 8 языков (`en`, `ru`, `uk`, `el`, `sr`, `bg`, `ro`, `ka`) с выбором из выпадающей сетки в меню-гамбургере.

- **Безопасность фокуса и совместимость с Vimium:**
  - Скрытый приёмник `#pp-keyboard-focus-receiver` в Shadow DOM удерживает фокус клавиатуры для работы хоткеев.
  - После любого перетаскивания окна или макета мыши фокус принудительно возвращается в приёмник, предотвращая случайный перехват клавиш расширением Vimium.

## Стандарты чистоты кода и архитектуры

- **Лимит размера файла (ориентир до 300 строк, допустимый порог до 320 строк) и изоляция логики компонентов:**
  - Базовый ориентир для файлов (`.ts`, `.vue`, `.sass`) — до **300 строк** (допустимый практический порог с учётом форматирования Prettier — до 315–320 строк). Если файл разрастается сильнее — его необходимо декомпозировать на подкомпоненты или логические модули.
  - **Колокация и зеркальное именование:**
    - Компоненты Vue именуются в PascalCase (`MockupFoldersAndList.vue`, `FloatingWindowHeader.vue`).
    - Локальная TypeScript-логика и Sass-стили компонента хранятся **строго рядом с компонентом** в той же папке и именуются в camelCase с маленькой буквы (`mockupFoldersAndList.ts`, `mockupFoldersAndList.sass`, `floatingWindowHeader.sass`, `mockupPositionControls.sass`).
    - В общих `composables/` хранятся только переиспользуемая межмодульная логика и глобальное состояние (`useStorage`, `useKeyboard`, `useTheme`, `useWindowDrag`).
    - В общей папке `styles/` хранятся только глобальные стили: дизайн-токены, темы, каркас окна (`_layout.sass`) и точка сборки (`floating-window.sass`).
- **Маленькие однозадачные функции:** Большие монолитные функции запрещены. Каждая функция должна выполнять ровно одно понятное действие и быть короткой.
- **Самодокументируемый код без комментариев-костылей:** Если внутри функции возникает необходимость написать поясняющий комментарий («что делает этот блок кода») — значит, этот блок должен быть вынесен в отдельную функцию с понятным для человека названием.
- **Понятные человеку названия (без непонятных аббревиатур):**
  - Использовать прозрачные, самоочевидные имена файлов, папок, констант и функций (`FloatingWindow.vue`, `MockupPositionControls.vue`, `MockupFoldersAndList.vue`, `FLOATING_WINDOW_HOST_ID`).
  - Не использовать аббревиатуру `HUD` / `hud` в коде и документации (использовать `floatingWindow` / «плавающее окно»).
- **Гигиена типов TypeScript:**
  - Избегать `any` (использовать строгие интерфейсы или `unknown` с проверкой типов).
  - Импортировать типы явно через `import type { ... }`.
